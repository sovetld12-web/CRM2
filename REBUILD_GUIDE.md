# 🔧 Инструкция по пересборке проекта на Amvera

## 📋 Проблема

Проект не пересобирается на Amvera. Возможные причины:
- Изменения не запушены в репозиторий
- Amvera кэширует старую конфигурацию
- Конфликт между старой и новой конфигурацией

## ✅ Решение

### Шаг 1: Проверьте что изменения запушены

Откройте терминал в папке проекта и выполните:

```bash
# Проверьте статус
git status

# Если есть изменения, закоммитьте их
git add .
git commit -m "fix: update amvera configuration"
git push origin master
```

**Важно:** Убедитесь что вы запушили в ветку `master` (или `main`, если она основная).

### Шаг 2: Проверьте подключение репозитория на Amvera

1. Откройте панель управления Amvera: https://cloud.amvera.io
2. Перейдите в ваше приложение `crm-lubov`
3. Откройте раздел **"Репозиторий"**
4. Убедитесь что:
   - Репозиторий подключён
   - Ветка: `master` (или `main`)
   - Токен доступа действителен

### Шаг 3: Запустите пересборку вручную

**Вариант A: Через интерфейс Amvera**

1. Откройте раздел **"Репозиторий"**
2. Найдите кнопку **"Пересобрать"** или **"Redeploy"**
3. Нажмите её
4. Дождитесь завершения сборки (5-10 минут)

**Вариант B: Через push в репозиторий**

Создайте пустой коммит для триггера пересборки:

```bash
git commit --allow-empty -m "trigger: rebuild on Amvera"
git push origin master
```

### Шаг 4: Проверьте логи сборки

1. Откройте раздел **"Логи"**
2. Выберите **"Лог сборки"**
3. Проверьте что:
   - Конфигурация валидна
   - Сборка прошла успешно
   - Нет ошибок конфигурации

**Ожидаемые логи:**
```
Configuration validated successfully
Starting build...
> npm install
> npm run build
✓ built in 8.54s
Starting application...
Server is running on 0.0.0.0:3000
```

**Ошибки которые должны исчезнуть:**
```
❌ Configuration error. Configuration file amvera.yaml must contain section 'meta'
```

### Шаг 5: Если пересборка не запускается

**Вариант 1: Очистите кэш Amvera**

1. Откройте раздел **"Настройки"**
2. Найдите **"Очистить кэш"** или **"Clear cache"**
3. Нажмите и подтвердите
4. Попробуйте пересобрать снова

**Вариант 2: Переподключите репозиторий**

1. Откройте раздел **"Репозиторий"**
2. Нажмите **"Отключить"**
3. Подключите репозиторий снова
4. Укажите ветку `master`
5. Запустите сборку

**Вариант 3: Создайте новое приложение**

Если ничего не помогает:

1. Создайте новое приложение на Amvera
2. Подключите тот же репозиторий
3. Настройте переменные окружения
4. Запустите сборку

## 🔍 Проверка конфигурации

### Текущая конфигурация amvera.yaml:

```yaml
meta:
  name: crm-lubov
  type: node

build:
  commands:
    - npm install
    - npm run build

run:
  command: node server.js
  port: 3000

env:
  - name: OPENAI_API_KEY
    required: true
```

### Альтернативная конфигурация (если текущая не работает):

Создайте файл `amvera.yml` (с одной `l`) со следующим содержимым:

```yaml
version: '1'

meta:
  name: crm-lubov
  type: node

build:
  commands:
    - npm install
    - npm run build

run:
  command: node server.js
  port: 3000

env:
  - name: OPENAI_API_KEY
    required: true
```

**Важно:** Amvera может использовать как `amvera.yaml`, так и `amvera.yml`. Попробуйте оба варианта.

## 🚨 Частые проблемы

### Проблема 1: "Configuration error"

**Решение:** Убедитесь что в `amvera.yaml` есть секция `meta`:
```yaml
meta:
  name: crm-lubov
  type: node
```

### Проблема 2: "Cannot find module 'express'"

**Решение:** Проверьте что в `package.json` есть `express`:
```json
"dependencies": {
  "express": "^4.18.2"
}
```

### Проблема 3: "dist/ not found"

**Решение:** Убедитесь что сборка проходит успешно:
```bash
npm run build
```

Проверьте что папка `dist/` создана.

### Проблема 4: Приложение не запускается

**Решение:** Проверьте логи:
```bash
# В интерфейсе Amvera
Логи → Лог приложения
```

Ищите ошибки при запуске `node server.js`.

## 💡 Если ничего не помогает

### Полная переустановка:

1. **Удалите приложение на Amvera**
2. **Создайте новое приложение**
3. **Подключите репозиторий заново**
4. **Настройте переменные окружения:**
   - `OPENAI_API_KEY` = `sk-ваш-ключ`
5. **Запустите сборку**

### Альтернатива: Используйте Docker

Если Node.js не работает, можно использовать Docker:

Создайте `Dockerfile`:
```dockerfile
FROM node:20-alpine

WORKDIR /app

COPY package*.json ./
RUN npm install

COPY . .
RUN npm run build

EXPOSE 3000

CMD ["node", "server.js"]
```

Обновите `amvera.yaml`:
```yaml
meta:
  name: crm-lubov
  type: docker

build:
  dockerfile: Dockerfile

run:
  port: 3000

env:
  - name: OPENAI_API_KEY
    required: true
```
